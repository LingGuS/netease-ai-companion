# 前端重构与后端接入计划

> 设计稿：[demo.html](demo.html)（1618 × 916，浏览器直接打开，顶部演示控制台可切换两种界面状态）
> 2026-10-31 起草；对应七步路线图收官后的「前端重构」阶段。

## 一、目标形态（与设计稿一致）

- 窗口固定 **1618 × 916**，仍由 `WindowTracker` 吸附在网易云桌面端右侧（吸附逻辑不变，仅窗口尺寸/内容重构）。
- 三栏布局：左「选择容器」300px + 中「歌曲容器」700px + 右「对话容器」618px（300+700+618=1618）。
- **两种界面状态**：
  | 状态 | 触发 | 布局 |
  | --- | --- | --- |
  | 纯对话 | 尚未推荐/播放歌曲 | 中+右合并为一个大对话板块（消息带头像） |
  | 推荐/播放中 | `done.cards` 出现可播放音乐卡 | 中=歌曲容器，右=对话（**无头像**，仅提问/回复文本） |
- 左栏从上到下：① 新建对话栏（高 76）② 历史对话列表（标题=首次提问的 LLM 总结）③ 用户信息（头像/昵称/VIP/设置图标，高 76）。
- 歌曲容器：主部分大封面 + 流动歌词（LRC 逐行高亮）+ 歌曲信息；底部播放条**高度同左三用户栏（76px）**：简要信息（小封面/歌名歌手/进度）+ 上一首、停止、下一首、歌曲列表按钮；列表点击后**向上弹出抽屉**，每列含封面、歌名、歌手、时长。

## 三、现有后端接口——直接复用，零改动

| 接口 | 用途 |
| --- | --- |
| `POST /chat/stream`（SSE：token/tool/done/error） | 对话主链路；done 携带 reply+cards |
| `POST /chat` | 兼容保留（流式关闭时兜底） |
| `POST /login/qr/start`、`GET /login/qr/check` | 设置弹层里的「扫码登录」（现有 QDialog 逻辑迁入 SettingsPopover 入口） |
| `POST /logout` | 设置弹层「退出登录」 |
| `POST /play/event` | QMediaPlayer 实际开播时上报（画像信号，保持） |
| `POST /feedback` | 赞/踩（若保留入口，可挂在中栏歌曲信息区） |
| `GET /me` | 登录态探测（字段增补见 §四-4） |

## 四、需新增/改造的后端（按实施顺序）

1. **会话登记语义**（小改）：现状前端启动生成一个 UUID 用满全程；重构后「新建对话 = 前端生成新 UUID + 直接发首条消息」。`/chat`、`/chat/stream` 已有 `upsert_session`，只需补充：当该 thread **首轮消息**时触发标题生成（见下条）。**不需要新建会话端点**。
2. **会话标题自动总结**：
   - `sql/05_add_session_title.sql`：`ALTER TABLE sessions ADD COLUMN title TEXT;`
   - `/chat/stream` 与 `/chat` 检测到首轮（checkpointer 该 thread 无历史）时，用 `asyncio.create_task` 后台调 DeepSeek 生成 6~12 字标题写 `sessions.title`（不阻塞 done 事件）；LLM 失败/超时兜底：截取首问前 12 字。前端在每次 `done` 后刷新会话列表即可看到标题从「新对话」变为总结标题。
3. **会话列表**：`GET /sessions?limit=50` → `[{session_id, title, last_active_at}]`（按 last_active_at 倒序；标题为空显示「新对话」）。可一并返回 message_count 便于展示（可选）。
4. **用户头像**：
   - `sql/06_add_user_avatar.sql`：`ALTER TABLE users ADD COLUMN avatar_url TEXT;`
   - `login._save_login_user` 落库时顺带从 `/user/account` 的 `profile.avatarUrl` 取头像存库（一次请求，无新调用链）；
   - `GET /me` 增补 `avatar_url` 字段；游客态前端显示占位头像。
5. **播放 URL 直取端点**（供上一首/下一首/列表点播，不经过 LLM）：
   - 把 `play_tools.play_song` 中「取元数据 + `/song/url/v1`（cookie 追加 os=pc）」抽成公共函数 `get_play_payload(song_id, level, cookie)`；
   - `POST /play/url` `{song_id, level?}` → 返回与卡片 payload 同构的 `{song_id, name, artists, album, cover_url, play_url, playable, trial_info, message?}`；
   - 播放 URL 保持永不落库（20 分钟时效签名链，实时取）。
6. **歌词端点**：`GET /lyric/{song_id}` → 调 music-api `/lyric/new`（经 store 缓存）返回 `{lrc, tlyric?}`；前端 `LyricsWidget` 解析 `[mm:ss.xx]` 行格式。
7. **卡片 payload 增补**（可选）：`play_song` payload 加 `duration_ms`（songs 表已有列），供队列与播放条显示总时长；不改协议结构。
8. **会话消息回放**：`GET /sessions/{id}/messages` → `graph.aget_state(config={"configurable":{"thread_id":id}})` 读 checkpoint，过滤掉 ToolMessage，转换为 `[{role, content}]`（AI 消息可附当时的 cards 便于回放）。切历史会话时前端加载渲染。
9. **明确不做**：会话删除/重命名接口（可后补）、播放队列持久化（前端会话内存态即可）、多账号切换。

## 五、前端工程结构与状态机

- 新模块划分（frontend-ui/）：
  - `main_window.py`：窗口 + 三栏骨架 + `AppMode` 状态机 + QSS 主题（#2B2828 体系 / #E04E4E 主色，与现有风格延续）；
  - `left_panel.py`：NewChatBar / HistoryList / UserBar + SettingsPopover；
  - `chat_panel.py`：由 chat_widget.py 重构——去掉顶栏登录（移入左③），气泡支持带头像/无头像两种模式，保留流式 token、工具状态行、卡片驱动；
  - `song_panel.py`：封面区 + LyricsWidget + PlayerBar + SongListDrawer；
  - `player.py`：PlayerController 扩展 `queue: list[payload]`、`index`、`next/prev/stop`、`current_changed` 信号；仍为全局单例。
- **状态机**：
  - `chat_only → now_playing`：`done.cards` 含 `type=music` 且 `playable=true` → 队列 append、PlayerController 播放、切页；
  - 游客/`playable=false`：仍切到 now_playing 但播放条置灰 + 提示「登录后可播放」（延续第 3.5 步降级策略）；
  - `now_playing → chat_only`：建议「停止播放且队列为空」时回合并态（是否自动回可做成设置项，默认回）。
- 对话容器在 B 态**不渲染音乐卡片气泡**——卡片只负责驱动中栏；试听/不可播提示以后端 `message` 字段以普通文本气泡呈现。

## 六、实施顺序（建议 5 步，每步可独立验收）

1. **纯前端骨架**：三栏布局 + 双状态切换 + 抽屉/弹层交互，全部假数据（对齐 demo.html 视觉）。
2. **对话链路**：ChatPanel 接 `/chat/stream` + `/me` + 扫码/登出迁移 → 真对话、真用户信息。
3. **会话体系**：sql/05 + GET /sessions + 标题生成 + GET /sessions/{id}/messages → 左栏真数据、切会话回放。
4. **播放链路**：sql/06 + /me.avatar_url + POST /play/url + GET /lyric/{id} + PlayerController 队列 + 歌词滚动 + 抽屉 → 中栏真数据。
5. **打磨**：QSettings 设置持久化、游客降级文案、异常/断线状态、低分屏缩放策略、回归测试（复用 scripts/chat_smoke.py 与离屏构造测试惯例）。

## 七、风险与注意点

- **标题生成的成本/风控**：每会话仅一次、后台任务、失败兜底截断；避免阻塞流式响应。
- **checkpoint 回放的消息形状**：历史里混有 ToolMessage/卡片数据，转换时务必过滤；卡片重放沿用 `_extract_cards` 的「遇到本轮 HumanMessage 停止」思路防重复。
- **1618×916 固定尺寸**：低分辨率屏会超出可视区域；WindowTracker 吸附逻辑不变，必要时按网易云窗口高度等比缩放（预留 `setFixedSize` → 比例缩放的开关）。
- **既有环境坑不受影响但需遵守**：Windows SelectorEventLoop（main.py 已处理）、Milvus Lite 单进程锁（跑迁移脚本前停后端）、@tool 的 config 参数必须带 `RunnableConfig` 注解。
- **游客态**：无播放 URL（`playable=false`）时中栏完整展示但播放按钮置灰 + 引导扫码，符合第 3.5 步「骨架等登录」策略。
